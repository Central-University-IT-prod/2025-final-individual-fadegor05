## `About`

В этом проекте имеется большое количество функционала так необходимого для рекламного аггрегатора:

- **Rest API** - само приложение, место, откуда ноги растут
- **Графики и статистика** - отдельный дашбоард с различными метриками и постороенными графиками по показателям рекламных кампаний и не только
- **Telegram бот** - удобное место для просмотра своей статистики у рекламодателей
- **Картинки** - никогда не помешают для привлечения внимания
- **Генерация текстов для реклам** - для ленивых или слишком занятых рекламодателей
- **Модерация** - против неадекватных или невнимательных рекламодатеей

## `How it works`

### `Rest API`

**Rest API**, реализованное по предоставленному ТЗ и `openapi.yml` спецификации. Есть некоторые расширения стандартного порядка эндпоинтов, увидеть обновленную `openapi` спецификацию можно через `Swagger`, по адресу `localhost:8080/docs`, для простоты расскажу про основные дополнения

#### `Картинки`

В схемах возврата **Рекламной кампании** добавлено поле `image`, а в схеме **Рекламы для пользователя** добавлено поле `ad_image`, которые присутствуют только, когда есть картинка, если ее нет, то они отсутствуют

В них имеется ссылка вида `http://localhost:8080/cdn/...`, которая возвращает файлы с `Minio` хранилища. Является эндпоинтом `GET /cdn/{slug}`

Добавлены отдельные эндпоинты `POST advertisers/{advertiserId}/campaigns/{campaignId}/image` для добавления картинки, `DELETE advertisers/{advertiserId}/campaigns/{campaignId}/image` для удаления картинки

#### `AI Генерация текста`

Добавлен эндпоинт `POST advertisers/{advertiserId}/generate/text`, который в контексте рекламодателя и предоставленного заголовка рекламы может создать текст самой рекламной кампании

#### `Банворды (Черный список слов для модерации)`

Добавлены эндпоинты `GET banwords`, `POST banwords/bulk`, `DELETE banwords/bulk`

### `Графики и статистика`

Для отображения статистики в проекте был выбрана популярная и хорошо зарекоммендовавшая себя **Open-Source** система визуализации данных **Grafana**, поддерживающия большое количество входных данных и довольно удобная для расширения.

**Дашбоард работает по адресу: `localhost:3000`, вход по данным логин `admin`, пароль `admin`**

Графики, выбранные для отрисовки:

#### `По дням`

- Общее количество показов
- Общие затраты на показы
- Общее количество переходов
- Общие затраты на переходы
- Общая конверсия

#### `Столбчатые`

- Показы по рекламным кампаниям
- Переходы по рекламным кампаниям
- Затраты на показы по рекламным кампаниям
- Затраты на переходы по рекламным кампаниям
- Общие показатели (показы, переходы, общие затраты на показы, общие затраты на переходы)
- Показы по рекламодателям
- Затраты на показы по рекламодателям
- Переходы по рекламодателям
- Затраты на переходы по рекламодателям

### `Telegram`

**Telegram бот** - проводник ко всей статистике для рекламодателей, оформленный в удобном и понятном исполнении. Вся статистика о рекламных кампаниях и о самих рекламодателях, по дням и общая.

#### `Как начать пользоваться`

Так как по заданию в проекте не предусмотрена регистрация и авторизация, привязка телеграм аккаунта к рекламодателю осуществляется по его уникальному идентификатору.

#### `Демонстрация работы`

Основная цель бота - отображение различной статистики, после входа в аккаунт рекламодателя, предстоит выбор:

- Общая статистика

В обоих случаях экран с информацией одинаков, сверху отображается аггрегированная статистика по контексту (тотальная, если общая статистика, либо общая по рекламной кампании, если статистика по рекламной кампании). Снизу отображается информация по дням, которые можно переключать по кнопкам ниже, также можно видеть изменение в процентах различных метрик, по сравнению с предыдущим днем.

### `Moderation`

Реализовано два вида модерации: банворды (черный список слов), ИИ (более погруженный в контекст), они могут работать как вместе, так и отдельно, для их настройки необходимо изменить переменные окружения **true/false**

```bash
MODERATION_BANWORDS=false
MODERATION_AI=false
```

## `Ad Algorithm`

Алгоритм показа рекламы работает таким образом:

1. Получение таргетированных предложений для клиента вместе с ML-оценками
2. Отсев нерелевантных кампаний, вычисляется максимальный ML-балл среди всех кампаний (используется для нормализации)
3. Получение данных по показам и кликам для всех полученных кампаний
4. Устанавливаются множители `IMPRESSION_SCORE_MULTIPLIER = 0.2`, если объясвление уже было показано, `CLICK_SCORE_MULTIPLIER = 0.01`, если на объявление уже нажали
5. Рассчитывается общий `score` по формуле: `score = (CPC x (ML Score/max ML Score) x 0.7) + (CPM x 0.4)`, где `CPC` - Cost Per Click, `CPI` - Cost Per Impression
6. Рекламная кампания с наибольшим `score` показывается пользователю

## `Why this stack?`

Стек выбранный для разработки данного проекта является релевантным и довольно оправданным. Он включает в себя технологии, использующиеся как в **Open-Source** разработке, так и в коммерческих проектах.

### `FastAPI`

Является популярным фреймворком для разработки веб API, с большим количеством дополнений, а также удобной интеграцией с Pydantic. На данный момент считается передовым и лидерующим по популярности фреймворком на равне с Django и Flask.

### `Postgres`

Мощная реляционная СУБД, поддерживающая сложные запросы и транзакции. Хорошо подходит для масштрабирования, поддерживает репликацию.

### `Minio`

S3-совместимое хранилище, позволяет эффективно управлять медиафайлами, например, рекламными изображениями. Благодаря совместимости с S3 API, он легко интегрируется с другими сервисами и обеспечивает быструю раздачу контента. Это решение удобно как для локального использования, так и для облачной инфраструктуры, а также гарантирует надежность хранения данных.

### `Aiogram`

Aiogram был выбран для разработки Telegram бота из-за своей асинхронной архитектуры. Он поддерживает удобную работу с состояниями (FSM), middlewares и callback-кнопками, что делает взаимодействие с пользователем интуитивным.

### `Aiogram Dialog`

Aiogram Dialog используется для удобного создания многошаговых диалогов в Telegram-боте. В отличие от стандартного Aiogram, он автоматически управляет состояниями и переходами между этапами, что делает код чище и упрощает сложные сценарии взаимодействия с пользователем.

### `Dishka`

Dishka используется в качестве Dependency Injection (DI) контейнера, что упрощает управление зависимостями и делает код более модульным и тестируемым.

## `Docker Compose`

### `Dockerfile`

Перед запуском всего проекта собирается его основная часть находящееся в папке `src`, откуда уже запускаются остальные контейнеры узкой направленности. Это помогает быстрее собирать весь проект, увеличивая скорость загрузки.

### `Server`

Основной FastAPI сервер, запускающийся с 4 асинхронными uvicorn воркерами через gunicorn из общего Dockerfile. Инициируется после проверки здоровья у `Postgres`, `Minio`, успешного запуска и завершения `Migrations`

### `Bot`

Telegram бот, тоже запускается из общего Dockerfile, после `Server`, успешного завершения `Migrations` и проверки здоровья у `Postgres`

### `Postgres`

Postgres база данных, запускается одной из первых

### `Grafana`

Дашбоард с различными графиками, запускается после проверки здоровья у `Postgres`

### `Migrations`

Контейнер с миграциями для базы данных, работающий при помощи Alembic, запускающийся после проверки здоровья у `Postgres`

## `Run & Tests`

Для запуска проекта через докер, необходимо просто выполнить команду:

```bash
docker compose up --build -d
```

Для запуска тестов используется `python` фреймворк `Tavern`, ее необходимо установить:

```bash
uv add tavern
```

После этого вы можете прогонять тесты, они работают за один проход, для их прохождения лучше предварительно очистить бд при помощи скрипта `clear_start.sh`, который удалит `docker volume` и запустит проект

```bash
uv run pytest
```
